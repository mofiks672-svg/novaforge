# Changelog

## 1.5.0
Анимации
- Заставка в ~1,5 раза медленнее: ковка логотипа ~3 с, плавнее экран загрузки, подчёркивание, печать подписи, блик и прощание; спиннер ответа — ~100 мс на кадр
- Настройка темпа: `"animation_speed"` в конфиге или `NOVA_ANIM_SPEED` (1 — по умолчанию, 0.7 — медленнее, 1.5 — быстрее, 0 — без задержек)
- Ковка логотипа снова при каждом запуске и в полной длине, как до 1.4.0 (~3,7 с: отдельный удар молота по каждой букве, долгая закалка и блик). Прежнее «раз в 6 часов» — `"intro_mode": "6h"`
- «Настройки»: режим заставки (каждый запуск / раз в 6 часов / выключена) и скорость анимации

Терминал
- Без мерцания: строки, которые обновляются на месте (спиннер, заставка, поле ввода, меню), больше не стираются перед перерисовкой — новый кадр пишется поверх старого одной записью, хвост дочищается после. Включён синхронный вывод (DEC 2026, Windows Terminal/современные терминалы), курсор скрыт во время перерисовки

Windows
- Установщик x64 (Inno Setup 6.7, `installer/windows`): тёмное оформление «Кузница», установка для себя или для всех, компоненты, папка проектов, страницы настроек — тема с живым превью, заставка и скорость анимации, разрешения ассистента, подключение API с ключом; PATH, профиль Windows Terminal, «Открыть NovaForge здесь» в Проводнике, ярлыки; при обновлении — «оставить текущие настройки»; аккуратное удаление
- Оформление установщика: новая графика (ковка с искрами на приветствии, готовый клинок и галочка на финише), индикатор шагов «Шаг N из M», акцентные подписи полей, «Показать ключ», советы во время установки, шпаргалка «Первые шаги» на последней странице
- Сборка установщика в Windows (`scripts/build-windows.ps1`) и в Linux без Windows (`scripts/build-windows-cross.sh`: llvm-mingw + Inno Setup под Wine)
- Настройки из установщика применяются при первом запуске (`installer-settings.json` → `config.json`, `auth.json`)
- Данные по умолчанию — `%APPDATA%\NovaForge` (существующая `%USERPROFILE%\.novaforge` продолжает использоваться)
- «Документы» определяются системным API: учитываются OneDrive и перенос папки
- Папка проектов, выбранная в установщике, используется, если в конфиге не задана своя
- `nova.exe` с иконкой и сведениями о версии, статический рантайм (не нужен VC++ Redistributable)
- Флаг `--cwd <папка>`

Проекты
- Новый проект получает `NOVA.md` — шаблон инструкций для ассистента; `/init` заполняет его по содержимому проекта. Отключается `"project_instructions": false`
- В папке проектов создаётся `Инструкция.md` с кратким руководством
- `/instructions` — какие инструкции читает ассистент; `/instructions edit` — открыть `NOVA.md` проекта, `/instructions global` — общие для всех проектов (Блокнот в Windows, `$EDITOR` в Linux/macOS); «Настройки → Общие инструкции»
- Установщик создаёт шаблон общих инструкций и ярлык «Общие инструкции NovaForge»

## 1.4.0
Модели
- Встроенной модели по умолчанию больше нет, как и зашитых списков моделей у провайдеров. Подключаете API — NovaForge загружает актуальный список с сайта провайдера (`GET /models`): новые модели сверху, embedding/TTS/whisper/модерация отфильтрованы, список сохраняется и обновляется по запросу (`/models refresh`, `nova models --refresh`, «Подключения API → Обновить список моделей»)
- Выбор модели — список с поиском (печатайте, чтобы фильтровать), прокрутка длинных списков, «Подключить API…» прямо из выбора модели
- Если модель не выбрана, первое сообщение предлагает подключить API или взять локальную модель — без ошибок «нет ключа»
- Удалена офлайн-модель `demo/nova`

Агенты удалены
- Нет встроенных и пользовательских агентов, субагентов, инструмента `task`, меню «Агенты», `nova agent`, `@агент`, `/agent`, `/agents`, `/create`, `/switch`, `/api/agents`. NovaForge — один ассистент
- Режим только чтения остался: `/plan`, `Shift+Tab`, `--plan`, в воркфлоу — `"mode": "plan"`
- Инструкции проекта — `NOVA.md` (`/init`); `AGENTS.md` и `CLAUDE.md` по-прежнему читаются. Старые воркфлоу с `"type": "agent"` работают без правок

Скорость
- Проверка локальных серверов (Ollama, LM Studio, llama.cpp) — параллельно и напрямую через сокеты вместо запуска curl на каждый порт. В Windows закрытый порт раньше «висел» ~2 с из-за повторов SYN — теперь ответ за миллисекунды
- Экран загрузки: все проверки выполняются одновременно; полная анимация ковки — не чаще раза в 6 часов, в остальные запуски логотип сразу
- Список сессий не читает истории целиком (кэш сводок) — меню «Продолжить сессию» и загрузка открываются мгновенно на больших архивах
- Windows: команды `bash` запускаются через `CreateProcess` и `cmd /d` (без AutoRun-скриптов), с таймаутом и прерыванием по Esc
- Windows: быстрая печать и вставка в поле ввода перерисовываются один раз, а не на каждый символ; меню перерисовываются без мерцания
- Вопросы «да/нет» отвечаются одной клавишей

Исправления
- Экран загрузки в консоли Windows: вместо спиннера рядом с «Локальные модели» и другими пунктами были квадраты «?» — шрифт консоли не содержит символов ▁▂▃▅▆▇. В классической консоли используется набор символов, которые есть в её шрифте; Windows Terminal и современные терминалы получают полный набор. Настройка `"glyphs": "auto" | "rich" | "safe"`, переменная `NOVA_GLYPHS`
- Текст загрузки: «разжигаю горы»
- Склонения в выводе инструментов («1 строка», «2 файла»)

## 1.3.0
Локальные модели
- Исправлено: Ollama и LM Studio не работали — в списке были модели, которых нет на сервере (`qwen2.5-coder` вместо `qwen2.5-coder:7b`, `local-model`); теперь список берётся с сервера, короткие имена дополняются
- Ollama работает через родной `/api/chat` с `num_ctx` (по умолчанию 8192): длинный промпт агента больше не обрезается молча
- Модели без поддержки инструментов (gemma, phi…) больше не падают с HTTP 400 — переход в режим чата с предупреждением
- Локальные адреса идут мимо `HTTP_PROXY`; `127.0.0.1` вместо `localhost` (IPv6 в Windows)
- Блоки `<think>…</think>` reasoning-моделей скрыты из ответа
- Автопоиск Ollama, LM Studio, llama.cpp при запуске; embedding-модели не предлагаются для чата; понятные ошибки «сервер не запущен» / «модель не установлена»

Интерфейс
- Чат в стиле Claude Code: карточка приветствия, поле ввода в рамке со строкой статуса, автодополнение `/команд` и `@файлов`, история, многострочный ввод, вставка через bracketed paste
- Вызовы инструментов `● Bash(…)` / `⎿ результат`, диффы правок, превью новых файлов, список задач ☐ ☒
- Подтверждение действий в рамке: «Да / Да, не спрашивать / Нет, сказать что иначе» — комментарий передаётся агенту
- Esc или Ctrl+C прерывают ответ и запущенные команды, а не закрывают программу; Ctrl+C дважды — выход
- Shift+Tab — режимы: обычный, авто-подтверждение, plan
- Анимации: загрузка со спиннерами и раскалённым прогресс-баром; ковка логотипа — нагрев, удары молота по буквам с искрами и встряской, закалка с паром, блик; подчёркивание и печать слогана; «горн гаснет» при выходе; спиннер ✻ с бегущим бликом
- Проекты: по умолчанию `default project` в `Documents/NovaForge`, экран «Проекты», пункт «Модель» в главном меню

Исправления
- `bash` без таймаута зависал навсегда на серверах и интерактивных командах — таймаут 120 с (параметр `timeout`), stdin закрыт, дочерние процессы завершаются вместе с группой
- Ошибка первого шага оставляла в истории повисшее сообщение пользователя
- Прерванный ход оставлял вызовы инструментов без ответов — следующий запрос отвергался API
- Генерация агента использовала модель по умолчанию вместо текущей
- `grep`: некорректное регулярное выражение давало непонятную ошибку, очень длинные строки могли переполнить стек
- Числа и булевы значения строкой (`"depth": "2"`) от локальных моделей игнорировались
- `/model` без провайдера всегда подставлял `openai/`
- Новое подключение к локальному адресу по умолчанию просило ключ

## 1.2.0
Запуск и меню
- Экран загрузки с реальными проверками окружения и прогресс-баром
- Анимация «ковки» логотипа NOVA FORGE (пропускается любой клавишей, `--no-intro`, `"intro": false`)
- Вопрос «Создать новую сессию?» — создаёт проект в `Documents/NovaForge` и открывает чат
- Главное меню со стрелками: сессии, проекты, агенты, подключения API, воркфлоу, настройки; `/menu` из чата

Агенты и API
- Подключения к любым OpenAI-совместимым API: URL, ключ, проверка соединения, автозагрузка моделей; `nova connect`
- Каждому агенту — своё подключение и модель (мастер создания и меню агента)

Оформление
- Градиентные темы `forge` (по умолчанию), `amber`, `phosphor`, `steel` в тёплой «металлической» гамме; `default` и `mono` остались
- Автоопределение глубины цвета: truecolor / 256 / 16
- Сообщения ✓ / ! / ✗ с отступами, экран не «замусоривается» при переходах по меню

## 1.1.0
Интерфейс
- Новый вывод в терминал: только стандартные ANSI-цвета терминала, без градиентов, truecolor-тем, ASCII-логотипа, эмодзи и рамок

- Корректная ширина строк с кириллицей, CJK и цветом; обрезка длинных строк больше не ломает escape-последовательности
- Убран встроенный веб-дашборд: `nova serve` теперь только JSON/SSE API

Исправления
- `/redo` после нового хода возвращал устаревшие изменения и мог перезаписать файлы
- Гонки данных в `nova serve`: создание/удаление агента во время выполнения запроса могло обрушить процесс
- Сессия в `nova serve` оставалась заблокированной навсегда, если запрос завершался исключением
- `--host` с некорректным адресом молча открывал сервер на всех интерфейсах
- Обход каталогов через имя воркфлоу в `POST /api/workflows` и через id сессии
- Внедрение shell-команд через поле `method` в http-шагах воркфлоу; кавычки в заголовках не работали в Windows
- `webfetch` падал с переполнением стека на больших HTML-страницах
- `glob`: запятая вне `{...}` ломала шаблон
- `read`: отрицательный или нулевой `limit` вызывал переполнение
- Удаление пользовательского агента, переопределявшего встроенный, приводило к падению
- Описание агента с переводом строки портило frontmatter
- Потоковые tool calls у провайдеров без поля `index` склеивались неправильно
- Подтверждения при передаче задачи через stdin молча отклонялись; теперь выводится понятное сообщение
- Сборка под Windows: `isatty` без `_isatty`
- Исключение в планировщике завершало весь процесс
- Escape-коды попадали в вывод при перенаправлении в файл

## 1.0.0 — стабильный релиз
- Интерактивный TUI со стримингом ответов и Markdown-рендером
- Агенты: build, plan, general, reviewer, docs, tester, automator + пользовательские (Markdown/JSON)
- Создание агентов: мастер, генерация через AI, REST API
- 12 инструментов: read, write, edit, multiedit, list, glob, grep, bash, webfetch, todowrite, todoread, task
- Субагенты (task / @агент), система разрешений allow/ask/deny, режим /yolo
- Сессии: сохранение, продолжение, undo/redo изменений файлов, сжатие контекста, экспорт в Markdown
- 11 провайдеров + любой OpenAI-совместимый API, офлайн demo-модель
- Автоматизация: воркфлоу (agent/shell/http шаги, условия, переменные), триггеры interval/watch, демон
- REST API + SSE-стриминг + веб-дашборд (`nova serve`), авторизация Bearer
- Кроссплатформенная сборка: Linux, macOS, Windows (Make/CMake), без внешних библиотек
